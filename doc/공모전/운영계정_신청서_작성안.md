# 공공데이터포털 운영계정 전환 신청서 작성안

대상 API: **KorService2 — 국문 관광정보 서비스** (대표 1개)

> 왜 이것인가 — 앱의 목록·검색·상세가 모두 이 서비스 위에 올라가 있어 호출량이 가장 크다.
> 나머지(무장애·반려동물·데이터랩·연관추천·사진수상작·다국어)는 보조 지표이거나 호출량이 적다.

> ⚠️ **제출 전 확정할 것** — 서비스 URL 이 문서마다 다르다.
> `1차심사_제출체크리스트.md` 는 `shimmaru.vercel.app`, `화면캡처_가이드.md` 는 `staymaru.vercel.app`.
> 아래 본문은 `staymaru.vercel.app` 로 적었다. 실제 운영 도메인으로 통일하고 두 문서도 함께 고칠 것.

## 2. 서비스 설명

```
「쉼(休)마루」는 한국관광공사 국문 관광정보 서비스(KorService2)를 기반으로 경상북도의
전통문화 자원을 탐색하고, 여행 일정을 자동으로 구성해 주는 웹 서비스입니다.

경상북도는 한옥·서원·사찰·전통시장·전통체험 등 전통문화 자원이 전국에서 가장 조밀하게
분포한 지역이지만, 자원이 22개 시·군에 흩어져 있어 방문객이 동선을 직접 설계하기
어렵습니다. 그 결과 경주·안동 등 소수 지역에 방문이 집중되고, 나머지 시·군의 자원은
충분히 알려지지 않았습니다.

본 서비스는 이 문제를 다음과 같이 해결합니다.

첫째, 경상북도(지역코드 35) 전역의 관광정보를 한옥·서원·사찰·전통체험·전통시장 등
전통문화 중심 카테고리로 재분류해 시·군과 카테고리를 교차로 좁혀 볼 수 있게 했습니다.

둘째, 이용자가 고른 지역·기간·취향을 바탕으로 방문 순서와 이동 동선까지 포함한
일차별 여행코스를 자동 생성합니다. 코스에 담기는 장소의 좌표·운영시간·휴무일은
관광정보 OpenAPI 의 상세 조회 결과를 그대로 사용합니다.

셋째, 한국관광 데이터랩의 지역별 방문자 통계를 함께 활용해 방문객이 적은 시·군을
'한적한 곳'으로 우선 추천합니다. 관광 쏠림을 완화하고 알려지지 않은 지역 자원의
방문을 유도하는 것이 본 서비스의 차별점입니다.

회원가입과 로그인 없이 누구나 이용할 수 있으며, 한국어·영어·일본어·중국어 4개 언어를
지원합니다. PWA 로 제작되어 모바일에서 앱처럼 설치해 쓸 수 있습니다.

서비스 URL : https://staymaru.vercel.app
서비스 유형 : 웹 (비영리 / 무료 / 회원가입 불필요)
```

## 3. 기능 및 서비스 화면

### 3-1. 화면별 API 활용 내역

| # | 화면 | 사용 오퍼레이션 (KorService2) | 활용 내용 |
| --- | --- | --- | --- |
| 1 | **카테고리 탐색** `/explore` | `areaBasedList2` | 경북 22개 시·군 × 전통문화 카테고리로 관광정보를 조회해 목록·지도로 표시. 카테고리별·시군별 자원 개수도 같은 오퍼레이션으로 집계 |
| 2 | **키워드 검색** `/explore` | `searchKeyword2` | '한옥·서원·탈춤·가야' 등 전통문화 키워드로 경북 내 자원 검색 |
| 3 | **장소 상세** `/place/:id` | `detailCommon2`<br>`detailIntro2`<br>`detailImage2` | 개요·주소·좌표·홈페이지(`detailCommon2`), 운영시간·휴무일·주차·이용요금·문의처(`detailIntro2`), 추가 사진(`detailImage2`) 표시 |
| 4 | **여행코스 자동생성** `/course` | `areaBasedList2`<br>`detailCommon2` | 선택한 시·군과 취향에 맞는 후보 자원을 조회하고, 좌표·운영시간을 근거로 일차별 방문 순서를 구성 |
| 5 | **지도 동선** `/course/map` | (3·4에서 받은 좌표 사용) | 코스에 담긴 장소의 `mapx`/`mapy` 로 방문 순서 마커와 이동 동선을 지도에 표시 |
| 6 | **축제 일정** `/festivals` | `areaBasedList2` (contentTypeId=15) | 경북 축제·행사 정보 및 대표 이미지 |
| 7 | **다국어 전환** 전 화면 | 동일 오퍼레이션 / EngService2·JpnService2·ChsService2 | 언어 전환 시 해당 언어 서비스로 동일하게 조회 |

### 3-2. 제출 화면 캡처

`화면캡처_가이드.md` 기준. 신청서에는 아래 4장이면 충분하다.

| 순서 | 화면 | 보여줄 것 |
| --- | --- | --- |
| 1 | `/explore` 카테고리 탐색 | 카테고리 탭 + 시군 필터 + 결과 목록이 채워진 상태 — `areaBasedList2` 활용 |
| 2 | `/place/:id` 장소 상세 | 대표 이미지 + 개요 + 운영시간·휴무일·문의처 — `detailCommon2` / `detailIntro2` 활용 |
| 3 | `/course` 코스 결과 | 지도 + DAY 1 / DAY 2 일차별 일정 |
| 4 | `/insights` 지금 경북 | 이번 주말 한적한 시·군 카드 — 데이터랩 연계 |

> 캡처에 **실데이터가 보여야** 한다. 목업·스켈레톤 상태는 심사에서 감점 요인이다.

## 4. 일일 트래픽 산정 근거 (요청량 기재 시)

운영계정 신청 시 일일 트래픽을 적게 되면 아래 근거를 쓴다.

**현재 구조에서의 호출량**

```
카테고리 탐색 화면 1회 진입 = 약 34회
  ├ 전체 개수            1회
  ├ 카테고리별 개수      11회
  ├ 시·군별 개수         22회
  └ 목록 조회            1회

조회 조건 조합 = 카테고리 11 × 시·군 23 = 253가지
장소 상세 = 1장소당 2~3회
```

**요청 근거 문구 예시**

```
경상북도 22개 시·군 × 전통문화 11개 카테고리를 교차 조회하는 구조로,
목록·개수 집계에만 화면당 약 30회의 호출이 발생합니다.
여기에 장소 상세(개요·운영정보·이미지) 조회가 장소당 2~3회 추가됩니다.

일일 이용자 1,000명 기준 약 3,000~10,000회의 호출이 예상되어
개발계정 한도로는 서비스 제공이 어렵습니다.

호출량을 줄이기 위해 서버에 통합 프록시와 요청 배칭을 두고 응답을
5분~24시간 캐시하고 있으며, 일 1회 배치로 경북 관광정보를 사전 적재해
이용자 요청 경로에서의 직접 호출을 최소화하고 있습니다.
```

> 실제 신청 수치는 포털에서 제시하는 구간 중에서 고르되, 위 계산을 그대로 사유에 적으면 된다.
